# TaskChef Next sidebar demo

Call `open_taskchef_board` in Codex to open **TaskChef Next**. The sidebar keeps the TaskChef List and Board views, project/date/status filters, task cards, and detail view. This demo gets its data from local Codex rollout logs. It does not read or modify the TaskChef dispatcher workspace. The web dashboard and dispatcher/report tools retain their current behavior.

Opening the board or calling a board tool triggers a scan when one is due. The server inventories `~/.codex/sessions/**/*.jsonl` and `~/.codex/archived_sessions/**/*.jsonl`, sorts by file modification time, and parses the 300 most recent files. The sidebar shows how many files were indexed, how many were parsed, and how many older files are outside that recent limit. The sidebar polls every five seconds while open. The server waits at least 30 seconds between ordinary scans and at least ten minutes between full reparses; these are minimum intervals, not background schedules. Each incremental scan inventories and stats all rollout files to detect new, changed, moved, and removed files. It reparses only new or changed files within the 300 most recent. Manual **Refresh** checks immediately. Closing the sidebar stops its polling, so no scans run while it is closed unless another board tool is called.

The scanner reads a bounded head and tail of each selected log. If the first metadata line crosses the usual 32 KiB head, it extends the head up to 1 MiB. It extracts session ID, timestamps, project directory, archive location, turn start/end events, and counts of visible user and assistant message records. It does not return request text, assistant text, tool outputs, or raw log records to the sidebar. Large logs can have unsampled content between the head and tail; the detail view shows the byte coverage. The sidebar shows a read-error count when selected files cannot be parsed. The scan is read-only and makes no model or GitHub calls.

A recent `task_started` event can mark a chat as **Working**, but this is only an activity hint and can lag the desktop app. When a large log has an unsampled middle and no turn event in its tail, recent file modification appears in the summary and `observed.recentFileActivity`. The chat remains **Unresolved** because the missing segment could contain a turn end. A `task_complete` event means that a turn ended, not that the user's task was completed. Such chats appear as **Unresolved**. This demo does not claim semantic completion, review, or merge. Archive location is shown as a file location, not as proof of task completion. The **Open chat** action navigates to the recorded Codex thread. There are no status transition tools in the sidebar.

The UI is the bundled `ui://taskchef/task-board/v2` MCP resource. Build it with `npm run build:mcp-app`; run `npm run check:mcp-app` and the relevant tests before release. Reopen the sidebar after rebuilding the resource.
